## The 12-Tier Hierarchy

From top (Edwin's position) to bottom (the work):

| Tier | Name | Role |
|---|---|---|
| 1 | **User** | Edwin — on the loop, not in it. Issues one prompt. Reviews one result. |
| 2 | **Manager** | Eva — routes tasks, monitors completion, keeps substrates in sync |
| 3 | **Workers** | Atomic agents — one skill, one task type, no polymaths |
| 4 | **Automation** | n8n, cron, webhooks — trigger + glue layer |
| 5 | **Workflow** | Defined sequences — the steps a Worker follows |
| 6 | **Instructions** | Agent INSTRUCTIONS.md files — the operating contracts |
| 7 | **Files** | Deliverables, inputs, outputs — the matter being shaped |
| 8 | **Folder** | Workspace directories — where files live |
| 9 | **Workspace** | The pre-built environment (Sofia-core, eva-gateway, etc.) |
| 10 | **Idea** | Edwin's raw intent — what prompted the prompt |
| 11 | **Engagement** | The interaction surface — Telegram, Claude Code, n8n UI |
| 12 | **Foundation** | T.G.A.O.T.U. itself — the geometry beneath all of the above |

## The 5 Operating Laws

1. **Workers are atomic, not polymathic.**
   One Worker = one task type. No "do everything" agents. Specialize or don't exist.

2. **Workflow improves with linear focus.**
   One task per Worker at a time. Parallel execution happens at the Manager tier, not inside Workers.

3. **Workplace is pre-built.**
   Edwin never sets up the environment. The workspace exists before the prompt arrives.

4. **User is on the loop, not in it.**
   Edwin provides the prompt and reviews the result. Everything between is the agent org's responsibility.

5. **Rest is a prompt away.**
   Any task — regardless of complexity — must be expressible as a single natural-language prompt.
