# Maverick Workplace Folder Rule

Maverick is not a dashboard-first project. Maverick is the Shift4 Dine
workplace folder.

The canonical surface is:

`/Users/edwinrosa/Library/Mobile Documents/com~apple~CloudDocs/Desktop/MAVERICK`

## Binding Direction

- Improve the `MAVERICK` folder before adding new interfaces.
- Keep the folder readable for Edwin and any invited collaborator.
- Put workflow, doctrine, indexes, handoffs, templates, and operating notes in
  the folder where they can be opened directly.
- Treat dashboards, repo packages, previews, and local servers as optional
  supporting views.
- Do not rename Maverick into a UI concept.
- Do not make the dashboard the product unless Edwin explicitly asks for that.

## Visibility Rule

Every Maverick work session must leave a visible folder artifact:

- a top-level index,
- a handoff note,
- a workflow update,
- a template,
- or a clear operating rule.

If a change only affects code or a dashboard, it is incomplete until the
`MAVERICK` folder tells a human what changed and where to work next.

## Current Folder Entry Points

- `WORKPLACE_INDEX.md` - plain-language starting point.
- `MAVERICK_WORKPLACE_RULE.md` - this rule mirrored into the folder.
- `MAVERICK_DOCTRINE.md` - operating doctrine.
- `DAILY_OPERATIONS_DECK.md` - daily work deck.
- `TEMPLATES/` - reusable messages and workflow templates.

The folder is the north star. Generated systems orbit it.
